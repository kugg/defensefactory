# Lessons carried into the skills

These procedures came from observed manually operated trials. They are
qualifications and safeguards, not a claim of reliable autonomous remediation.

| Observation | Procedure or helper response |
| --- | --- |
| An agent inspected/checked out source before publishing scope despite instructions. | Manual operator kickoff precedes fresh-worker launch; the runner requires the ticket-backed opening. Record operator intervention explicitly. |
| Builds and debugging bypassed a cumbersome JSON capture interface. | `stage-exec.py` wires opening/challenge bindings for direct argv and preserves producer failure codes. Arbitrary host tools can still bypass it. |
| A mutant build could not use the exact command required for the test evaluator. | A declared support role permits setup/build/runtime for known subjects; it cannot earn mutation-detection credit. |
| A generic startup error looked like a security refusal. | Require the expected guard diagnostic, valid positive and changed-control legs, raw child output and prospective assertions. |
| A failed revision query was treated as exhausted indexing capability. | Inspect the actual configured host/API capability, job, ref and branch policy within budget. An empty optional profile field is not proof of absence. |
| A guessed endpoint returned 404; a create request with a response-only field returned 400. | Inspect the deployed client/handler and actual request schema. Do not report a caller error as a missing backend capability or repeat the identical failing body. |
| A mutant artifact was run under a baseline command binding. | Support producers must explicitly select the variant. Record the executed binary/image's source and build identity; a structurally valid command binding alone does not prove artifact provenance. |
| A generic error was attributed to missing dependencies without a diagnostic. | Separate observation from causal hypothesis, measure duration from timestamps, and keep runtime inconclusive without discriminating controls. |
| An evaluation assertion failed before its evidence was saved. | Save observations before expectations, retain Git bundles on failure and keep a fallback repository if bundling fails. A later successful run does not erase the first failure. |
| An archive was published without separately retrievable requirements. | Publish, retrieve and verify both assets before claiming ticket-only handoff. |
| A chosen final subset verified while failed captures were omitted or mislabeled. | Finished captures retain execution-receipt typing and dependencies regardless of result; reconcile the full attempt inventory. The helper cannot discover wholly omitted runs. |
| A comparison printed a Boolean but had no portable recipe and input snapshots. | `evidence-compare.py` saves inputs, selectors, expectation and result; receivers replay it from archived bytes. Console persistence is distinct from ticket persistence. |
| A full native response existed only in the client's private output cache. | The inventory snapshots truncated-response caches, preserves provenance/redaction limits and exports selected tool observations without private reasoning. |
| An artifact's label matched the candidate while its build/use lineage was absent. | Build bindings observe clean Git inputs, retain payload/spec/log/actual build receipt, and reject mismatched source or changed/unused payloads before runtime. |
| A container shell printed child exit 2 but returned zero itself. | Named process assertions inspect the actual producer exit; inline shell/echo wrappers cannot earn runtime assertion credit. |
| A worker declared completion before later actions and publication. | Live snapshots cover an observed prefix. A separate finalized parent-runner audit can qualify the report; no unreviewed command silently becomes a pass. |
| Setup/comparison admission rejected legitimate work and the agent fell back to legacy capture. | Baseline setup has a supported path; comparisons are published exact subjects. Registered-trial legacy capture is refused before launch; rejection receipts are retained. |
| Runtime assertions were deleted after an inline-shell rejection. | Prepare fixtures separately, freeze direct artifact probe plans, and reject/report protocol downgrades against saved declarations and refusals. |
| CodeIntel connected but no source work happened. | Schema-2 handoffs require a scoped disposition and actual native query/raw index evidence; discovery alone is insufficient. Missing work is not a service failure. |
| Local mutant hashes/generator survived but exact Git objects did not. | Export selected local commit objects into verified named Git bundle refs, with portable dependency receipts; retain export failures. |
| Historical success was confused with work performed in a fresh attempt. | Freeze inputs per attempt, recover state from the live ticket, and keep current execution, historical input and observer recovery distinct. |

Claims remain developer-owned and portable. A test/lint/type fence constrains
behavior; guidance explains intent. A valid owner amendment is not automatically
tampering, and a matching bug class is not evidence that an occurrence is covered.

The ticket is the authoritative handoff, but ticket text does not grant host
permissions. Endpoint configuration does not prove authentication or index
coverage. A receipt transports evidence; populated fields, a zero exit status,
a model label, a finite-model result or a structurally complete bundle do not
establish the semantic correctness of a repair.

Fresh-worker adherence must be measured separately from deterministic helper
tests. The manual bootstrap changes the experimental condition; it is not
independent-agent acceptance. Protected identities, capability isolation and
production governance require separately designed and evidenced controls.

[State, capture and replay](skills/defensefactory/references/handoff-state.md)
defines the local/ticket boundary and the new helper contract. The changes are
prospective: historical reports, receipts and frozen installations retain their
original qualifications.

## Partial fixtures and approved-input continuation

The latest continuation exposed gaps after source export had been approved. A
selected source archive lacked an imported dependency; a test name was guessed
before discovery; a host lacked the assumed timeout executable; and no
candidate-bound runtime probe ran. The prospective fixture assembler retains
approved inputs, explicit overlays and adequacy paths under a distinct fixture
subject. Go discovery can bind selected names to the same frozen evaluators.
Image/tool preparation remains project-specific, captured work under the actual
scope, not an unspecified owner-approval dependency.

Required runtime probes now belong to the published scope and cannot disappear
behind empty worker requirements or passing fixture/unit checks. Tests exercise
real child exits and sealed build/use graphs, including offline replay after
source paths are erased. They do not establish a product's call coverage.

The worker's exported requirements were narrative JSON rather than the emitted
machine inventory. A hash-matched download was therefore not a complete handoff.
Bundle preparation now writes its exact requirements sidecar, and paired native
readback checks both assets without manual signed-URL copying. Failed generations
are retained; supplements do not rewrite earlier compliance. Status recovery
uses current invocation paths and measured timing, then requires a live ticket
refresh: a compacted summary had briefly restored an obsolete approval hold.

These are prospective helper/procedure changes. Earlier frozen attempts remain
qualified, unchanged experimental evidence. A separate fresh live trial is still
needed to measure agent adherence, compaction recovery and supported E2E behavior.
