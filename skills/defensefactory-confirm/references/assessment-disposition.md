# First assessment: does this finding still apply?

Choose the gate's purpose explicitly using the [scoped-source procedure](handoff-completeness.md). Bounded `source_assessment` needs authorized trial subjects, not a complete deployment inventory. Historical/report/comparison gaps are not mandatory trial targets by default. Complete release/deployment scope remains mandatory for lifecycle closure; source-only continuation cannot waive unresolved repair requirements or grant a lifecycle transition.

Read the [preflight procedure](experiment-preflight.md) for target roles, observation-only receipts, mandatory gate ordering and actual-performer review bindings. Missing inventory does not authorize inventing one. It defers lifecycle disposition while already-authorized source investigation may continue. Hypothetical comparisons always deny closure. This revision requires actual scope completeness/reference and verified review-record bindings for terminal decisions; legacy name-only policy fixtures do not gain new-version authority.

For bounded nonactive source completion, use the [assessment resolution procedure](assessment-resolution.md): `stop_source` finishes the selected source task without a native lifecycle transition.

Run this gate before repair contracts, Mermaid exposure analysis or E2E-guidance questions. Fetch the original finding and current ticket scope, supported-target inventory and requirement authority. Source-only and deployed-artifact scopes differ: a fix on main cannot close a finding covering an old deployed release. Missing source, an inaccessible repository, a partial extraction or zero search hits remain unresolved.

Before this gate can qualify an early stop, include the complete current-ticket
`authority_review` from the [assessment resolution procedure](assessment-resolution.md).
Map every current owner resolution or constraint into `repair_decisions`, even
when the proposed source disposition is `already_fixed`; a new attempt/opening
does not reset earlier owner requirements. The helper rejects an omitted mapped
decision. The source/fix analysis must evaluate the implementation against those
retained choices, not merely against the ticket title or reporter's original
suggested patch.

For each required target record its exact source revision or artifact/configuration, component identity, original report, scope-review authority, inventory reference and evidence. The invoker supplies trusted scope and permitted actors/operations separately; the finding cannot exclude its own targets or grant closure rights. Review the actual authoritative decision, not just its populated fields or a reviewer name. Helper hashes validate correspondence, not factual truth or identity isolation.

* **Removed:** inspect both immutable Git trees with `component-inspect`. Establish the original file existed and is absent now. Renames/copies continue assessment. Review successors/replacements in the selected tree for source completion; review all declared supported releases for lifecycle disposition; Git inspection alone cannot establish that a component was retired everywhere.
* **Retired/deprecated:** require the actual owner/support-policy decision excluding the target and record the remaining unsupported risk. A deprecation annotation alone does not qualify, and disqualification is not a claim that old installations are secure.
* **Already fixed:** bind current target, fix/source analysis and security, positive-behavior and regression checks to exact evaluator identities. Retain commands, exit codes, nonzero named-test counts, zero unexplained skips and verified raw logs. A merged PR or failed exploit alone is insufficient. Use runtime checks when the target scope requires them; do not demand a runtime for a justified source-only decision.
* **Active/unknown/mixed:** continue for active targets; unresolved targets hold whole-ticket closure. Preserve individual dispositions instead of hiding a still-affected target behind a closed one.

`assess-eligibility` accepts `{packet, policy, actor}`. `packet` contains `case`, per-target `subject/reason/evidence`, hashed evidence records, the current-ticket `authority_review` and mapped `repair_decisions`. `policy.assessment_scopes[case].targets` is the complete trusted target inventory (each has `id`, exact `subject`, and, for fixed decisions, `required_checks` with `id/kind/evaluator_sha256`). `policy.assessment_reviewers` identifies authorities whose external decisions the invoker has actually verified. Each scope-review record binds `target/subject/reviewer/decision/rationale/original_report/inventory_reference`. Removal also needs `git:{repo,before,after,path}` and replacement/release review. Retirement needs `retirement_authority/support_decision/remaining_risk`. Fixed scope reviews also identify the reviewed fix and current-source analysis. Required checks enumerate named tests; check records bind executed test names, commands/timestamps, results, evaluator, log reference/hash and test counts; `packet.raw_logs` supplies the retrieved log text for hashing. These records and policy must be recovered through ticket resources, not authored merely to satisfy a schema. The helper does not authenticate reviewer identity; use the environment's governing review/authorization mechanism.

Use `assess` with `eligibility:{packet,policy,actor}`. Valid close/disqualify results return before requiring a claim or test plan; missing eligibility holds. An active result continues normal assessment. Carry only its active targets forward, preserving excluded-target decisions.

The portable `scripts/ticket_handoff.py` can render an early assessment checkpoint with `early_disposition`, pinned `disposition_receipt_reference/disposition_receipt_sha256` and `target_scope_reference`, without inventing a repair contract. Its prose readback guard does not replace exact evidence-byte validation.

Publish an append-only disposition receipt and referenced proof to the ticket, including per-target reason, authority, reviewed source/retirement/fix evidence, limitations and policy identity. Verify resource bytes and readback. Map the decision to the project's native lifecycle status and reason using discovered team configuration. Apply the authorized transition through the ticket connector, read back status/reason and stop the pipeline. A helper output does not mutate the ticket; do not claim closure until that readback succeeds. If no matching lifecycle status/permission exists, publish the concrete blocker. Existing user authorization suffices within its scope; do not invent another approval requirement. Preserve the original report. New support/target facts or invalidated fix evidence reopen/reassess through the native lifecycle.
