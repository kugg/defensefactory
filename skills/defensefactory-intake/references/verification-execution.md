# Exact-candidate verification

Follow [state, capture and replay](handoff-state.md) for build/use bindings,
predeclared actual-child assertions and the whole evidence inventory. A later
runtime probe does not supply a missing build capture. Console output and local
client caches must become saved, replayable ticket resources before handoff.

For new v6 attempts, first follow [stage admission and capture](trial-controls.md). Use the guarded execution path and retained receipt dependencies; legacy helper success does not establish stage admission.

Recover the case's candidate, claim, frozen evaluator/check definitions, guidance, formal disposition and code-evidence policy through the live ticket. Verify their referenced bytes and actual decision status before running code. Run `verify` in the portable `scripts/stage.py` against a full Git revision. The helper extracts clean source and limits process time; it does not establish an OS sandbox or protected identity. Preserve raw logs and failed runs; a repair summary cannot stand in for the verifier's own execution.

Check definitions include `execution`, which is covered by the claim's frozen check-spec digest. Existing contracts without a protocol become incomplete verification, not silently amended contracts. Select the product's actual test framework or supply an explicitly reviewed adapter:

* `format: go-test-json`: run the case-selected Go command with fresh tests (`-count=1`) and `-json`. `required_tests` contains fully qualified `package::TestName` identities, including required subtests. A package-only pass or empty regex match cannot satisfy it.
* `format: factory-jsonl-v1`: a verified project adapter emits `FACTORY_TEST ` followed by JSON with `candidate`, `check_id`, `name` and terminal `status` (`passed`, `failed`, `skipped`). The runner supplies `FACTORY_CANDIDATE_REVISION` and `FACTORY_CHECK_ID`. Freeze a nonempty `required_tests` inventory. The adapter remains evaluator code requiring review; emitting a claimed result does not authenticate it.
* `format: command`: for a deliberate non-test assertion, provide `reason` and `success_criteria`. Exit status establishes only that command's assertion. It claims no named-test coverage and cannot silently substitute for required product tests.

Every required test must pass. Missing events, malformed/mixed-subject records, zero tests and unexplained skips are inconclusive. A failure remains violated even if another run passes or the wrapper exits zero. Optional skips need named reasons in frozen `permitted_skips`; a required test cannot be excused by this list. Actual process nonzero/timeout, command, UTC timestamps and raw-log hashes remain visible separately from qualified test coverage. Missing implementation bindings or changed extracted inputs cannot earn complete verification.

Formal results are separate: a matching profile/scenario digest, completed safety result and reachable positive scenario establish only the declared model result. When formal checking is required, `implementation_evidence` binds the exact candidate, claim digest, implementation file hash map and all required executed check IDs. The model result alone does not satisfy this correspondence. The source-to-model mapping and evaluator adequacy still need substantive review; this transport check is not a proof of arbitrary implementation semantics. Do not use another project's model to satisfy the case.

Use `verification-report` to combine the runner result with a ticket-backed contract. It binds case, the full `required_obligations` ID-to-check map, subject revision, claim/evaluator/check identities, exact guidance object digest, E2E gates and a declared CodeIntel policy. Supplied guidance does not prove execution; required journeys need exact candidate/plan observations and complete real legs. A justified source-only non-E2E scope remains explicit. Required exact-source CodeIntel evidence cannot be omitted; an unavailable/out-of-scope disposition must be explicitly recorded under the governing contract. Retain CodeIntel requests/responses, warnings and coverage instead of using model-generated descriptions as source evidence.

The result routes violated obligations to repair, stale subjects to refreshed evaluation and incomplete checks to concrete prerequisites. A complete same-host report is ready for integration review. It does not merge, deploy, close a finding or assert independent acceptance. Publish the raw receipt/resources, verify ticket readback/byte hashes using the shared ledger protocol, and have integration re-fetch the ticket and evaluate the actual merge subject. Preserve previously failed obligations and mutant counterexamples across iterations. Bounded challenges need confirmed unmet obligations and the ticket's round/time budget; repeated speculation cannot add rounds.
