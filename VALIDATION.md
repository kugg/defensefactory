# Validation scope

Validated on 2026-11-13. These are bounded checks of this experimental package.

The canonical component-rules update plus JER-36 evaluator corrections passes
**79 offline tests** in this repository. Sixteen focused checks exercise the strict Markdown grammar,
semantic/prose diffs, Unicode and hidden-content rejection, external descriptor
validation, CUE/CodeQL/Semgrep/test/Markdown adapter behavior, candidate/evaluation
separation, coverage-aware zero-finding semantics, unavailable engines, detached
source mutation, native-owner change admission, legacy migration with preserved
project guidance, component/repository moves with available or unavailable
introduction history, explicit enforcement-downgrade reporting, and soft-only
evidence that cannot admit a claim. The disposable Git/Python `eval-rules.py` evaluation also
passes: adequate zero-finding coverage satisfies its synthetic baseline, an
unevaluated candidate stays inconclusive, a separately confirmed candidate
violates the claim, and the exact-subject integration gate blocks it. These are
mechanical helper checks; they do not install a native required check, authenticate
review objects, isolate host processes/network, perform security evaluation, or
prove live-agent adherence.

synthetic; model/service traffic is mocked or absent. This is not a new live

One intermediate development packaging evaluation failed on the expected missing-
history result before it saved the observation. Its cause was not established.
The evaluator now saves observations before assertions and retains both Git
repositories on failure. During the capture/handoff update, the exported matrix
reproduced the symptom and retained a concrete Go setup failure: access to the
host-default build cache was denied, with zero named tests executed. The evaluator
now uses a private disposable writable cache and records the selected toolchain.
This explains the newly preserved failure; it does not prove the earlier
unrecorded failure had the same cause. Failed output/fixtures remain preserved.

Live agent trials required manual scope bootstrap and operator correction. They
still showed capture/provenance mistakes, unsupported causal attribution and
incomplete exact-source indexing/runtime checks. Those results stay qualified in
their original ticket records. The new helper checks are prospective corrections,
not evidence that a fresh agent will consistently follow the workflow. Evaluate
that separately before expanding operational scope.
